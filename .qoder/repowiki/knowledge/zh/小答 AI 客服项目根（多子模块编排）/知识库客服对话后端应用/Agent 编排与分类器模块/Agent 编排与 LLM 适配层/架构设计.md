模块由三个文件构成清晰的三层结构：
- `llm.py` 定义 LLM 抽象接口与两种实现——`DeepSeekClient`（基于 OpenAI SDK 的流式/非流式调用）和 `MockLLM`（按提示词关键字路由的规则化输出），并由单例 `llm = LLM()` 根据 `settings.use_real_llm` 自动切换，是上层唯一依赖。
- `orchestrator.py` 中的 `Orchestrator` 类是主入口，`process_turn` 串联「用户要求转人工 → 防死循环熔断 → 确认状态机 → 并行情绪分级+查询重写 → 红灯熔断 → 混合检索 → decide 决策 → NLI/布尔判断 → 高风险 FAQ 拦截 → `_answer_flow` 流式生成 + 事实校验」的完整管线，通过 `AsyncGenerator` 产出 `{type: meta|text|done}` SSE 事件流；内部 `_hard_handover` / `_soft_handover` / `_answer_flow` 等私有方法封装不同分支逻辑。
- `copilot.py` 提供坐席侧辅助能力：`extract_ticket` 用 LLM 结构化摘要、`generate_templates` 基于知识库上下文生成快捷回复模板、`build_copilot_for` 异步落库工单卡片，以及开发期 Mock 的内部系统查询（物流/订单/退款）。
依赖方向单向：`orchestrator` → `llm` + `intent/emotion/humor/prompts` + `storage.kb`；`copilot` → `llm` + `storage.kb`；三者不互相引用，LLM 抽象是稳定边界。
